## 一、服务端：已经跑起来了

本地 Node 服务通过 Cloudflare 隧道对外暴露：

```
https://drawing-molecular-trustees-municipal.trycloudflare.com
```

已验证公网全链路：登录 → 载入相册 → 随机一天 → 发起交换 → 对方接受 → 双向展示。

**注意三件事：**

1. 这是**临时隧道**，不只是进程一停地址就失效 —— 实测它还会被 Cloudflare 主动回收
   （4 天内必挂）。重新开：`./scripts/tunnel.sh`，拿到新地址后改
   `miniprogram/config.js` 的 `BASE_URL`，**重新上传一次**才生效。
2. 服务跑在你这台 Mac 上。**关机 / 合盖休眠，朋友的体验版就打不开。**
   要长期给人玩，得放到一台常开的机器上（云服务器、家里的 NAS、旧笔记本都行）。
   —— 也正是这条，让「只做体验版」这件事的天花板很明显：它适合给几个朋友玩几天，
   不适合当成一个真在运营的产品。
3. 判断隧道是否真的活着，别看进程，`curl` 一下：

   ```bash
   curl -s https://<你的地址>/api/health
   ```

## 四、朋友扫码后必须做的一步（关键）

体验版在真机上**默认仍然校验服务器域名白名单**，而我们用的是临时的 trycloudflare 域名，
不在白名单里，会报 `request:fail url not in domain list`。

解法：让朋友在小程序里打开调试模式——

1. 微信里打开这个小程序
2. 点右上角 **···**
3. 选 **开发调试**
4. 小程序会重启，右上角出现 vConsole 图标，这时就能正常请求了

这一步每次重装/清除缓存后可能要重做。烦，但体验版只能这样。

## 六、可能会卡住的点

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| `不存在此 AppID (code 10)` | 还是测试号，没填真实 AppID | 改 `project.config.json` 的 appid |
| `request:fail url not in domain list` | 没开开发调试 | 右上角 ··· → 开发调试 |
| 停在登录页转圈 | 隧道挂了 / Mac 休眠了 | 重开隧道，改 `config.js` 重传 |
| 上传报 `unbound appid` | 登录的微信不是该小程序的管理员/开发者 | 公众平台 → 成员管理，把当前微信加为开发者 |
| 提示需要先备案 | 部分情况体验版也会拦 | 公众平台 → 设置 → 备案信息，走小程序备案（个人可办，免费，约 1-2 周） |
| **隧道进程还在跑，域名却打不开** | 临时隧道被 Cloudflare 回收了。进程会一直重试并刷 `Unauthorized: Tunnel not found`，但救不回来 | `pkill -x cloudflared` 后重开，改 `config.js` 的 `BASE_URL`，重新 `upload` |

最后一条是实际踩到的：**临时隧道活不过几天**。10-24 那次的地址在 10-27 已经死了三天，
进程一直显示「在跑」，实际每次请求都失败 —— 所以别用 `pgrep` 判断隧道是否可用，
直接 `curl` 一下 `/api/health` 才作数。
